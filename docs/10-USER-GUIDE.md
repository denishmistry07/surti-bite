# Operator user guide

## Start a shift

Open the app on the usual browser/device. Check the header date and session. Tap the session banner to open the store with the correct business date and shift. New sales need an open session. If a previous shift is still open, review it before closing or creating another.

## Take an order

1. Search or select a menu category.
2. Tap Add or + and adjust quantities. Selected products have a green outline/background.
3. Open Show details to review line items. Use − or × to correct mistakes.
4. Enter an Adjusted amount only for an extra amount to charge. Example: two Oil Locho at ₹50 plus ₹20 adjustment = ₹120.
5. Select Dine-in/Takeaway and Online/Offline payment. Add a reference if the field is enabled.
6. Save & Close. Watch for sync completion before treating the server record as confirmed.

Weight badges describe quantity: a 120g item shows 240g for two portions and 1.2kg for ten. Weight is informational and does not calculate an adjustment automatically.

## Multiple customers

Use New to create another open order and tap its chip to switch back. Orders stay on the current browser. Clear All removes the active cart's items and adjustment after confirmation. Discard only the intended order.

## If internet fails

New orders can be saved to the local queue using the last loaded menu/session state. A banner shows pending/offline/failed sync and Retry. Keep using the same browser and preserve site storage. Reconnect and wait for the banner to clear. Do not enter the same sale again merely because synchronization is slow. A closed server session or changed menu can require administrator help; Retry cannot correct every validation error.

## Correct a saved sale

Open History, find the order and tap Edit. Review the separate editable cart, change items/payment/type/adjustment and choose Update order. Retained items keep their original price. An inactive/deleted product may prevent editing. Saved-order updates require the backend connection; they do not use the new-sale offline queue. Cancelled orders cannot be edited.

Cancel keeps the record but excludes its revenue from reports. Delete removes the record and is not a routine correction method. Only use these actions when authorized by the owner.

## Track expenses and returns

Use Expenses to add the actual purchase cost, business date, Operating/Investment classification, payment and description. Record payer/fund details when relevant. Edit the existing expense for corrections. For a linked fund return, use its settlement/return action rather than recording the purchase expense again.

## Review results

Today shows the active business date. Reports provides day/month/year results and PDF export. History supports search, date ranges and other filters. Online/Offline describe recorded payment selections. If a manual spreadsheet correction is not visible, ask the administrator to reconcile the derived data.

## Settings

Optional bottom tabs can be enabled/disabled and saved. Order, Menu and Settings remain. Under Sync & backups, inspect summary refresh time, pending updates, backup/recovery dates and any error. Refresh checks the latest recorded backend status. Request timings are local diagnostics, not a promise of speed.

## Finish a shift

Ensure pending orders have synchronized, review payment totals, then close the store session. Do not clear browser data with pending orders. Report incorrect totals, missing backups or repeated sync failures to the assigned administrator.
